Spotlight: the skill that sets this pack apart

Most tools stop at telling you what went wrong in an agent. This one fixes it in your code, proves the fix, and keeps it fixed.

Biggest selling point

Fix agents test-first, and keep them fixed

fix-agent-issue
EXPLORE

Reads the bad trace, logs the complaint on it, writes a diagnosis. No code edits yet.

PLAN

Turns the complaint into regression tests and proves they fail on today's agent.

IMPLEMENT

Smallest change at the layer that's actually wrong: tool, retrieval, routing or prompt.

VERIFY

Runs the full suite so nothing else breaks, then asks you to review one new trace.

Guarded in CI

The tests are plain pytest. They run on every pull request, so the failure can't quietly return.

Why it matters

  • Works in your repo, from the trace to the exact line of code.
  • Handles new business rules too, and asks whether a rule applies everywhere or only in some cases before writing tests.
  • Refuses quick prompt patches for problems that are really a missing tool or missing data.

Try asking

  • This answer is wrong. Fix it. Trace tr-1234.
  • New business rule: when the agent discusses a member's costs, it must state the member ID it looked up.

Spec-driven, test-first, verified: the same AI-DLC discipline, applied to agents.

Guardrails built in

Every skill carries rules that steer the assistant away from common, costly mistakes. These are good prompts to try in a demo.

If someone asks…The skill makes the assistant…
"Just use whichever profile comes first."List every workspace profile and wait for you to choose. It never guesses a workspace.
"Run databricks sql execute."Explain that the command doesn't exist, and use the CLI's real query tool.
"Partition the table and ZORDER it."Recommend Liquid Clustering, the better default for new tables.
"Extend this old import dlt pipeline code."Migrate it to the current pipelines API first, instead of building on legacy code.
"It failed once, just do a full refresh."Warn that a full refresh can lose streaming state, suggest a selective refresh, and ask first.
"Train it on my laptop and move it to Production."Train on the platform as a job, and use the @prod alias because stages are deprecated.
"Hard-code this model name for my agent."List the model endpoints actually available in your workspace first.
"It says READY, query the endpoint now."Check that the version swap has also finished, so you're not testing the old model.
"Skip MLflow, just write a quick evaluation loop."Use MLflow's evaluation APIs, so every result stays tracked and comparable.
"Skip the tests and patch the prompt."Push back once, write a failing test first, and fix the layer that's actually wrong.

Before you start

  • Databricks CLI v1.0.0 or later, and a logged-in profile.
  • MLflow 3.14.0 or later for the agent-quality skills.
  • jq and a bash shell for trace and session analysis. On Windows, use WSL2 or Git Bash.
  • uv for agent-evaluation, and pytest for fix-agent-issue.
  • Genie Code runs in notebooks. Where a skill shows shell commands, ask it to use the Python APIs instead.
